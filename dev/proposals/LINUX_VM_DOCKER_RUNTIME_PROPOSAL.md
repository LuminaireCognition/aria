## Executive Summary

`aria-init` writes bootstrap files to `data/` with legacy filenames and calls bare `python3`. The rest of the codebase — session boot, CLAUDE.md, docs, the pilot registry — already uses `userdata/pilots/{id}_{slug}/` with canonical filenames and `uv run python`. This proposal fixes `aria-init` to match, adds a lightweight runtime advisory, and defers Docker to a future proposal contingent on validation gates.

- **This proposal:** Rewrite `aria-init` to emit files into the canonical `userdata/pilots/` layout with canonical filenames. Replace `python3` with `uv run python`. Add `uv` prerequisite check. Add runtime detection with a one-line advisory. Add platform support statement to `README.md`. One-time cutover, no migration machinery.
- **Future proposal:** Docker as quick start, contingent on MCP topology and OAuth validation gates.

Canonical onboarding narrative:
- macOS and Linux are supported platforms.
- For Windows 11 users, the documented path is WSL2 as the Linux environment.
- Docker quick start is deferred until validated in a separate proposal.
- Linux VM remains a hardened/advanced deployment option.

## Problem Statement

1. `aria-init` writes bootstrap files to `data/` with legacy filenames (`pilot_profile.md`, `operational_profile.md`, etc.), while every runtime consumer reads from `userdata/pilots/{id}_{slug}/` with canonical filenames (`profile.md`, `operations.md`, etc.).
2. `aria-init` calls bare `python3` for OAuth setup despite project policy requiring `uv run python`.
3. `aria-init` does not update `userdata/pilots/_registry.json` or `userdata/config.json`, so the files it creates are invisible to session boot.
4. `aria-init` does not verify that `uv` is available before invoking Python.

The `data/` directory does not currently exist on disk. The live installation already uses the v2 layout. This means `aria-init` is broken on re-run and would create a parallel, orphaned file tree if executed today.

Evidence:

- `docs/FIRST_RUN.md` uses `userdata/pilots/...` paths.
- `CLAUDE.md` session init resolves active pilot from `userdata/config.json` and `userdata/pilots/_registry.json`.
- `aria-init` hardcodes `DATA_DIR="$SCRIPT_DIR/data"` (line 24) and writes all six bootstrap files there (lines 296-301, 366, 514, 577, 694, 785, 883).
- `aria-init` displays legacy paths in completion output (lines 1216-1221) and test mode (lines 1342-1368).
- `aria-init` calls bare `python3` for OAuth (lines 1192, 1195, 1200).

## Goals

1. Make `aria-init` produce files that the rest of the system can actually find.
2. Document the pilot directory naming contract (`{character_id}_{slug}`) with equivalent implementations in bash and Python.
3. Print a one-line runtime advisory in `aria-init` so users know their platform status.
4. Add platform support statement to `README.md`.

## Non-Goals

1. Native Windows shell support.
2. Backwards compatibility with the `data/` layout (it was never consumed by the v2 runtime).
3. Docker containerization (deferred to a future proposal).
4. Perfect runtime fingerprinting or VM detection.
5. Runtime enforcement policies or runtime classification in boot hook JSON output (add if a real need emerges).

## `aria-init` Rewrite to Canonical Layout

### What changes

Rewrite `aria-init` to:

1. **Check `uv` availability** inside `check_prerequisites()`, after argument parsing. The `--help` and `--version` flags must remain usable without `uv` installed — the check only gates execution paths that invoke Python (ESI setup, OAuth handoff) or file operations. `--force` skips confirmation prompts on corrupt JSON recovery and placeholder adoption (see below) but still requires `uv` for the subsequent init:
   ```bash
   if ! command -v uv &>/dev/null; then
       echo "Error: uv is required but not found on PATH."
       echo "Install from https://docs.astral.sh/uv/"
       exit 1
   fi
   ```

2. **Write files to `userdata/pilots/{character_id}_{slug}/`** instead of `data/`. Use canonical filenames directly:
   - `profile.md` (was `pilot_profile.md`)
   - `operations.md` (was `operational_profile.md`)
   - `ships.md` (was `ship_status.md`)
   - `missions.md` (was `mission_log.md`)
   - `exploration.md` (was `exploration_catalog.md`)
   - `goals.md` (new — not in legacy `aria-init`; generated by heredoc in `aria-init`)
   - `industry/blueprints.md` (was `industry/blueprint_library.md`)

3. **Update `userdata/pilots/_registry.json`** with the new pilot entry. All fields for a new entry: `character_id`, `character_name`, `directory`, `faction` (default `"Unknown"`), `account_tag` (default `"main"`), `created_at`, `last_active`. Timestamps use UTC ISO 8601 format (`YYYY-MM-DDTHH:MM:SSZ`). `created_at` is set once on first creation; `last_active` is set on every write. Bash: `date -u +%Y-%m-%dT%H:%M:%SZ`. Python: `datetime.datetime.now(datetime.timezone.utc).strftime('%Y-%m-%dT%H:%M:%SZ')`. Existing fields (`faction`, `account_tag`, `last_active`) are preserved for compatibility with `pilot-resolution.sh` (reads `faction` for display) and `.claude/scripts/aria-oauth-setup.py` (updates `last_active` on existing entries).

4. **Update `userdata/config.json`** to set `active_pilot` to the new character ID.

   **Applicability:** Steps 3 and 4 apply only when `character_id != 0`. When `character_id == 0` (fresh clone, no credentials), `aria-init` writes profile files only — no `_registry.json` entry, no `config.json` update. The placeholder directory exists on disk but is invisible to session boot until OAuth assigns a real ID.

   **Write ordering and recovery (when `character_id != 0`):** Steps 2–4 must execute in strict order: profile files first, then `_registry.json`, then `config.json`. Each JSON write uses a temp-file-then-rename pattern to avoid partial writes (see per-language specifics below). If the process fails between steps, the state is recoverable:
   - Failure after step 2 (files written, no registry entry): `aria-init` re-run detects the directory and offers overwrite/keep/backup. No phantom registry entry exists.
   - Failure after step 3 (registry written, no config update): `aria-init` re-run finds the registry entry and reuses the directory. `active_pilot` can be set manually or by re-running init.

   **Atomic write implementation:**
   - **Bash (`aria-init`):** Acquire a non-blocking advisory lock via `mkdir` (POSIX-portable), then `mktemp "$path.tmp.XXXXXX"` → write → `mv` (atomic rename on same filesystem). No `fsync` — the power-loss-mid-write failure mode is not a realistic threat for a single-user CLI tool. Pattern:
     ```bash
     _lockdir="$path.lock"
     if ! mkdir "$_lockdir" 2>/dev/null; then
         echo "Error: Another ARIA process is writing $path"; exit 1
     fi
     trap 'rmdir "$_lockdir" 2>/dev/null' EXIT
     mktemp "$path.tmp.XXXXXX"  # → write → mv
     rmdir "$_lockdir"
     ```
     The `mkdir` failure branch above is simplified — see **Stale lock recovery** below for the full lock acquisition pattern with automatic stale-lock breaking.
     **Rationale:** `flock -n` (`util-linux`) is not available on macOS, which is a declared supported platform. `mkdir` is atomic on all POSIX filesystems and provides the same non-blocking, fail-fast semantics without platform-specific dependencies. The lock directory is cleaned up via `trap` on exit to prevent stale locks after crashes. Python uses the same `mkdir`-based mechanism for cross-language lock compatibility (see below).
   - **Python (`.claude/scripts/aria-oauth-setup.py`):** Uses the same `mkdir`-based lock as Bash for cross-language compatibility. Pattern:
     ```python
     import os, errno, tempfile, json
     lockdir = f"{path}.lock"
     try:
         os.mkdir(lockdir)
     except OSError as e:
         if e.errno == errno.EEXIST:
             raise RuntimeError(f"Another ARIA process is writing {path}")
         raise
     try:
         fd = tempfile.NamedTemporaryFile(
             mode='w', dir=os.path.dirname(path), suffix='.tmp', delete=False
         )
         try:
             json.dump(data, fd)
             fd.flush()
             os.fsync(fd.fileno())
             fd.close()
             os.replace(fd.name, path)  # atomic, same-fs guaranteed by dir=
         except:
             fd.close()
             os.unlink(fd.name)
             raise
     finally:
         os.rmdir(lockdir)
     ```
     **Note:** `dir=os.path.dirname(path)` ensures the temp file is on the same filesystem as the target, which is required for `os.replace()` to be atomic. `os.replace()` is used instead of `os.rename()` because it explicitly documents cross-platform atomic-replace semantics (Python 3.3+). On POSIX both are equivalent, but `os.replace()` makes the overwrite intent unambiguous.
     **Rationale:** Using the same `mkdir`-based mechanism in both Bash and Python avoids a lock namespace conflict — if Bash creates `config.json.lock/` as a directory and Python expects it as a file (for `fcntl.flock`), a stale lock from a crashed Bash process would cause Python's `open()` to fail with `IsADirectoryError`. A single lock mechanism eliminates this cross-language interaction hazard.
   - **Scope:** Locking applies to `config.json` and `_registry.json` writes only. Lock directories are per-path (`config.json.lock/`, `_registry.json.lock/`). Non-blocking (`mkdir` fails immediately if directory exists) so contention fails fast rather than deadlocking.
   - **Stale lock recovery:** `trap EXIT` (Bash) and `try/finally` (Python) handle normal cleanup, but neither runs after `SIGKILL`, OOM-kill, or power loss. Since ARIA is single-user with no concurrent writers, a stale lock is always safe to break. Recovery policy:

     **Error message (mandatory):** Lock contention errors MUST include the lock path and removal instructions:
     ```
     Error: Lock exists at {lockdir}. If no other ARIA process is running, remove it:
       rmdir {lockdir}
     ```

     **Automatic recovery (recommended):** Before failing, check the lock directory's mtime. If older than 300 seconds (no ARIA operation takes 5 minutes), break the lock automatically with a warning:
     - **Bash:**
       ```bash
       if ! mkdir "$_lockdir" 2>/dev/null; then
           _lock_age=$(( $(date +%s) - $(stat -c %Y "$_lockdir" 2>/dev/null || echo $(date +%s)) ))
           if [ "$_lock_age" -gt 300 ]; then
               echo "Warning: Stale lock detected (${_lock_age}s old). Breaking lock."
               rmdir "$_lockdir" 2>/dev/null && mkdir "$_lockdir" 2>/dev/null || {
                   echo "Error: Could not break stale lock at $_lockdir"; exit 1
               }
           else
               echo "Error: Lock exists at $_lockdir (${_lock_age}s old)."
               echo "If no other ARIA process is running: rmdir $_lockdir"
               exit 1
           fi
       fi
       ```
       **Note:** `stat -c %Y` is Linux-only. On macOS, use `stat -f %m`. Detect at script start: `if stat -c %Y / >/dev/null 2>&1; then _STAT_MTIME="stat -c %Y"; else _STAT_MTIME="stat -f %m"; fi`.
     - **Python:**
       ```python
       import time
       try:
           os.mkdir(lockdir)
       except OSError as e:
           if e.errno != errno.EEXIST:
               raise
           lock_age = time.time() - os.path.getmtime(lockdir)
           if lock_age > 300:
               print(f"Warning: Stale lock detected ({lock_age:.0f}s old). Breaking lock.")
               os.rmdir(lockdir)
               os.mkdir(lockdir)
           else:
               raise RuntimeError(
                   f"Lock exists at {lockdir} ({lock_age:.0f}s old).\n"
                   f"If no other ARIA process is running: rmdir {lockdir}"
               )
       ```

   **JSON merge semantics:** Updates to `config.json` and `_registry.json` MUST preserve all existing keys not being modified. Implementations MUST read the existing file (if present), merge changes into the loaded structure, and write back the full document — never construct the file from scratch. This prevents unintentional deletion of non-core keys (e.g., `redisq` block in `config.json`, `schema_version` in `_registry.json`).
   - **Bash (`aria-init`):** Read with `jq`, set target key(s), write back. Example: `jq '.active_pilot = "1234"' config.json > "$tmpfile" && mv "$tmpfile" config.json`. If `jq` is unavailable, fall back to `uv run python -c 'import json, sys; ...'` for the merge step only (acceptable overhead since this runs once at end of init, not in the hot path). The fallback uses only stdlib (`json`, `sys`) — no third-party packages are imported, so `uv run` works offline on a bare checkout without `uv sync` having been run. Detection: `command -v jq &>/dev/null` at the start of the JSON write helper, cached for the session.
   - **Python (`.claude/scripts/aria-oauth-setup.py`):** `json.load()` → `data[key] = value` → atomic write. This is the natural pattern and already preserves unknown keys.

   This ordering ensures the registry never references a directory that doesn't exist, and `active_pilot` never references a pilot that isn't in the registry.

   **Writer exclusivity:** `config.json` and `_registry.json` have **one writer at a time by design**. `aria-init` is interactive and foreground-only. `.claude/scripts/aria-oauth-setup.py` is invoked from `aria-init`. Background scripts (`.claude/scripts/aria-boot-sync`, `.claude/scripts/aria-token-refresh.py`) run at session start, not during init. An advisory lock (`{path}.lock/` via `mkdir` in both bash and Python) is acquired around every JSON write to `config.json` and `_registry.json` as defense-in-depth — since this proposal touches all writers, the marginal cost of adding locks now is lower than retrofitting them when a future change introduces concurrent writers.

   **Corrupt JSON recovery:** If `_registry.json` or `config.json` exists but fails JSON parsing, the file is backed up to `{filename}.corrupt.{timestamp}` (e.g., `_registry.json.corrupt.20260207T230100Z`) before being treated as empty. A warning is printed naming the backup file. This prevents silent data loss from partial writes or filesystem corruption while preserving the "does not crash" behavior.

   **Confirmation gate after corruption recovery:** After printing the corruption warning (and orphan detection output, if applicable), `aria-init` prompts for confirmation before proceeding:
   ```
   Existing state was recovered as empty due to corruption.
   Continue with fresh initialization? [y/N]
   ```
   Default is abort (N). This prevents a transient filesystem issue from silently resetting pilot registration. The `--force` flag (new) skips this prompt for scripted use. When `config.json` is corrupt but `_registry.json` is healthy, the confirmation message also lists registered pilots from the registry so the user can see what `active_pilot` should be restored to.

   **Orphan detection after registry recovery:** When `_registry.json` is recovered as empty, `aria-init` must scan `userdata/pilots/` for existing non-placeholder directories (i.e., directories not matching `0_*`) and warn about each one that is not in the (now-empty) registry:
   ```
   Warning: Found pilot directory 'userdata/pilots/2123984364_federation_navy_suwayyah/'
   not referenced in registry. It may contain data from before the corruption.
   The backup registry is at: _registry.json.corrupt.20260207T230100Z
   ```
   This makes orphaned state visible without blocking the init process. The user can manually restore the backup registry or re-register the pilot.

   **`active_pilot` ownership rule:** When `character_id` is known (non-zero), `aria-init` and `.claude/scripts/aria-oauth-setup.py` use different policies matching their intent:

   - **`aria-init`** (bootstrap tool): **always set `active_pilot`** to the current pilot's character ID, overwriting any previous value. Running init for a pilot implies intent to use that pilot.
   - **`.claude/scripts/aria-oauth-setup.py`** (credential tool): **set `active_pilot` only if not already configured** (preserve the existing `if not config.get("active_pilot")` guard). OAuth is used to add alts or refresh tokens — it should not silently switch the default pilot as a side effect.

   This split respects the existing multi-pilot architecture (`docs/MULTI_PILOT_ARCHITECTURE.md`, `pilot-resolution.sh`) where `active_pilot` is an explicit user choice, not a last-writer-wins side effect.

5. **Replace `python3` with `uv run python`** at all OAuth invocation points (lines 1192, 1195, 1200).

6. **Update completion output** to show the actual paths created (`userdata/pilots/{id}_{slug}/profile.md`, etc.) instead of `data/pilot_profile.md`.

7. **Update test mode** (lines 1342-1368) to match the same canonical layout.

### Pilot directory naming contract

- Format: `{character_id}_{slug}`
- `character_id`: numeric string from ESI OAuth, or `0` as placeholder during init before OAuth.
- `slug`: ASCII-only normalization of the character name. Steps: (1) lowercase, (2) spaces replaced with `_`, (3) strip all characters outside `[a-z0-9_]`, (4) truncate to 32 chars, (5) empty result falls back to `pilot`. Non-ASCII characters (accented, CJK, etc.) are stripped — not transliterated.
- If the pilot already exists in the registry, reuse the existing directory path (no rename).

The slug algorithm is simple enough (~4 lines) that it is implemented separately in bash (inside `aria-init`) and Python (inside `.claude/scripts/aria-oauth-setup.py`). The contract is documented here; both implementations must produce identical output for the same input.

**Implementation constraints:**
- **Bash:** Must use `LC_ALL=C` and explicit ASCII ranges (`[a-z0-9_]`), NOT POSIX classes (`[[:alnum:]]`) which are locale-dependent.
- **Python:** Must use `re.sub(r'[^a-z0-9_]', '', s)`, NOT `str.isalnum()` which matches Unicode alphanumerics.

Both constraints ensure only ASCII characters survive the filter, regardless of the host locale or Python's Unicode-aware builtins.

The test suite should include a shared set of test vectors validated against both implementations:

| Input | Expected Slug |
|-------|---------------|
| `"Federation Navy Suwayyah"` | `federation_navy_suwayyah` |
| `"x"` | `x` |
| `""` | `pilot` (empty fallback) |
| `"A B-C.D'E"` | `a_bcde` (space→underscore preserved, punctuation stripped) |
| `"aaaa..."` (40 chars) | first 32 chars (truncation) |
| `"Érinya Découverte"` | `rinya_dcouverte` (accented chars stripped) |
| `"名前テスト"` | `pilot` (all stripped → empty fallback) |
| `"Tëst Pïlöt"` | `tst_plt` (non-ASCII vowels stripped) |
| `"  Spaces  Everywhere  "` | `spaces__everywhere` (leading/trailing spaces become underscores, interior preserved) |

Rejected alternative: shelling out from bash to `uv run python -c ...` for slug generation. This introduces a Python dependency at a point where `uv sync` may not have been run yet, and adds ~500ms of startup overhead for a 4-line string operation.

### Pilot resolution precedence in `aria-init`

When `aria-init` needs to identify which pilot to operate on (for registry lookup and re-run detection), it follows a precedence chain mirroring the runtime resolution in `pilot-resolution.sh`:

1. **`ARIA_PILOT` env var:** If set, use this character ID as the target pilot. Look up in `_registry.json`; if found, reuse the existing directory.
2. **`active_pilot` in `userdata/config.json`:** If the config file exists and contains `active_pilot`, use this character ID. Look up in `_registry.json`; if found, reuse the existing directory.
3. **Single registry entry:** If `_registry.json` exists and contains exactly one pilot, use that pilot's character ID and directory.
4. **Multiple registry entries, no selector:** Fail with an explicit error listing the registered pilots:
   ```
   Error: Multiple pilots in registry and no pilot selected.
   Registered pilots:
     - Federation Navy Suwayyah (2123984364)
     - Alt Character (9876543210)
   Set ARIA_PILOT=<character_id> or update active_pilot in userdata/config.json.
   ```
5. **Zero registry entries:** No target pilot; proceed to character ID resolution below.

### Character ID resolution (no registry match)

When pilot resolution yields no registry match, `aria-init` resolves the character ID as follows:

**Selector-aware shortcut:** If pilot resolution identified a target ID via `ARIA_PILOT` or `active_pilot` (steps 1–2 above) but found no matching registry entry, `aria-init` must use that ID directly — construct the credential path as `userdata/credentials/{id}.json` and skip the directory scan below. This prevents a missing/corrupt registry from causing `aria-init` to ignore an explicitly selected pilot and fall through to ambiguous credential scanning. The directory scan in case 1 below only applies when no selector was set (i.e., steps 1–4 all fell through).

1. **If ESI credentials exist in `userdata/credentials/`:** scan for files matching the strict pattern `^[0-9]+\.json$`. Non-numeric filenames (e.g., `.gitkeep`, `backup_old.json`) are ignored. If exactly one candidate is found, extract the character ID from its filename (e.g., `2123984364.json` → `2123984364`) and use this ID for the directory name. If zero candidates are found, fall through to case 2. If multiple candidates are found, fail with an explicit error listing the files:
   ```
   Error: Multiple credential files found in userdata/credentials/:
     2123984364.json
     9876543210.json
   Cannot determine which character to initialize. Remove extras, keeping only
   the credential file for the character you want to use.
   ```

**Enforcing the known-ID directory invariant:** When the character ID is resolved from credentials (case 1 above), `aria-init` must scan `userdata/pilots/` for existing directories matching `{id}_*` before creating `{id}_{slug}`. This mirrors the placeholder invariant below and prevents duplicate directories for the same character ID when the registry is missing or corrupt:
- If zero `{id}_*` directories found: create `{id}_{slug}` normally.
- If exactly one `{id}_*` directory found: reuse it — treat as a re-run and fall through to existing-file detection (overwrite/keep/backup). The existing directory's slug is preserved (no rename).
- If multiple `{id}_*` directories found: fail with an explicit error:
  ```
  Error: Multiple directories found for character ID 2123984364:
    userdata/pilots/2123984364_federation_navy_suwayyah/
    userdata/pilots/2123984364_fed_navy/
  Cannot determine which to use. Remove duplicates, keeping only one.
  ```
  This prevents nondeterministic directory selection at runtime (`auth.py:624` uses `startswith(pilot_id)` and returns the first filesystem-order match, which is undefined on ext4).

Without this invariant, re-running `aria-init` with a different typed name while the registry is absent/corrupt creates a second directory for the same character ID. The runtime then silently picks whichever directory `iterdir()` returns first.

2. **If no credentials exist (fresh clone):** use `0` as the character ID placeholder. The directory becomes `0_{slug}` (e.g., `0_federation_navy_suwayyah`). No registry entry or `config.json` update is created by `aria-init` in this case (see "Applicability" above).

**Enforcing the single-placeholder invariant:** Before creating a `0_{slug}` directory, `aria-init` must check for any existing `0_*` directory in `userdata/pilots/`. If one is found:
- If it matches the computed slug (`0_{slug}` is the same directory): treat as a re-run — fall through to existing-file detection (overwrite/keep/backup).
- If it has a different slug (e.g., prior run used a different name): print an error and exit:
  ```
  Error: Found existing placeholder directory 'userdata/pilots/0_alice/'.
  A placeholder directory already exists from a previous run.
  Options:
    1. Re-run aria-init with the same character name to update it.
    2. Delete the old directory: rm -rf userdata/pilots/0_alice/
    3. Run OAuth first to assign a real character ID: uv run aria-esi auth
  ```
  This prevents accumulation of multiple `0_*` directories.

When `.claude/scripts/aria-oauth-setup.py` later runs, it must detect and adopt the placeholder directory:

1. After OAuth completes and the real character ID is known, search `userdata/pilots/` for directories matching `0_*/`.
2. **If zero `0_*` directories found:** current behavior (create new directory and registry entry) is unchanged.
3. **If exactly one `0_*` directory found:** adopt it (see rename step below).
4. **If multiple `0_*` directories found:** fail with an explicit error:
   ```
   Error: Multiple placeholder directories found in userdata/pilots/:
     0_alice/
     0_bob/
   Cannot determine which to adopt. Remove all but one and re-run.
   ```
5. **Rename with collision check:** Before renaming `0_{old_slug}/` → `{real_id}_{old_slug}/`, check if `{real_id}_{old_slug}/` already exists. If it does, fail with an explicit error:
   ```
   Error: Target directory 'userdata/pilots/2123984364_federation_navy_suwayyah/' already exists.
   Cannot rename placeholder directory '0_federation_navy_suwayyah/'.
   Remove the placeholder directory if it is no longer needed:
     rm -rf userdata/pilots/0_federation_navy_suwayyah/
   ```
6. If the collision check passes: rename `0_{old_slug}/` → `{real_id}_{old_slug}/` via `mv`, preserving the original slug from the placeholder directory name. The slug is not regenerated from the ESI-returned character name — any mismatch between the user-typed name in `aria-init` and the ESI-returned name is cosmetic and not worth the complexity of re-slugging. The registry entry uses the ESI-returned character name for `character_name` but the preserved slug for `directory`.
7. Create the registry entry and update `config.json` with the real character ID.

`.claude/scripts/aria-oauth-setup.py` does not currently implement this rename logic. It must be added as part of this proposal (see Implementation Plan).

This avoids placeholder registry entries that `.claude/scripts/aria-oauth-setup.py` would then need to reconcile.

### Re-run behavior (existing canonical files)

When `aria-init` detects existing files at the canonical path (`userdata/pilots/{id}_{slug}/profile.md`), the existing `handle_existing_installation()` logic (lines 1239-1290) applies, updated to reference canonical paths:

- **Overwrite:** delete canonical files, regenerate.
- **Keep existing:** exit without changes.
- **Backup & replace:** copy canonical directory to `userdata/pilots/{id}_{slug}.bak.{timestamp}/`, then regenerate.

The function's file list and directory references change from `$DATA_DIR/pilot_profile.md` etc. to `$PILOT_DIR/profile.md` etc. The logic and user-facing options remain the same.

**Existing V2 installation (current state):** The live installation already has a populated `userdata/pilots/2123984364_federation_navy_suwayyah/` with real profile data. Running the rewritten `aria-init` on this installation hits case 1 of character ID resolution (pilot exists in registry), reuses the existing directory, and offers the standard overwrite/keep/backup options. No automatic changes are made to existing data.

### Post-OAuth first-run (directory exists, no profile files)

`docs/FIRST_RUN.md` suggests running OAuth as step 1. In the current implementation, `.claude/scripts/aria-oauth-setup.py` creates the registry entry but does NOT create the pilot directory. This proposal adds pilot directory creation to `.claude/scripts/aria-oauth-setup.py` (see implementation plan step 18) so that the directory exists when `aria-init` runs afterward. After this change, `.claude/scripts/aria-oauth-setup.py` creates the registry entry and pilot directory but does NOT generate profile templates. When `aria-init` subsequently runs:

1. Character ID resolution finds the existing registry entry (case 1).
2. The pilot directory exists but contains no profile files (no `profile.md`, etc.).
3. `aria-init` detects this as an empty directory — not a re-run with existing files — and generates templates without prompting for overwrite/keep/backup.

The detection logic: check for the pilot directory's existence AND the presence of **any canonical file** within it. The canonical file set is: `profile.md`, `operations.md`, `ships.md`, `missions.md`, `exploration.md`, `goals.md`, `industry/blueprints.md`. Directory exists + no canonical files = populate. Directory exists + any canonical file exists = re-run prompt (overwrite/keep/backup).

This prevents a crash mid-init (e.g., `operations.md` written but process killed before `profile.md`) from silently overwriting the partially populated directory. It also protects manually created files that happen to use canonical names.

If a `data/` directory exists from a previous `aria-init` run, emit a message:

Note: Found legacy data/ directory. This is no longer used by ARIA.
If you have no custom data there, you can delete it: rm -rf data/

Do not auto-delete. Do not migrate. The canonical files already exist in `userdata/pilots/`.

### Runtime detection

Add a `detect_runtime()` bash function to `aria-init` with five detection cases:

| Priority | Check | Classification |
|----------|-------|----------------|
| 1 | `[[ "$(uname -s)" == *MINGW* ]] \|\| [[ "$(uname -s)" == *MSYS* ]] \|\| [[ "$(uname -s)" == *CYGWIN* ]]` | `unsupported` |

## Rejected Alternatives

1. **Data migration machinery** (quarantine, identity proof, collision-safe backups, transaction journals): The `data/` directory does not exist. The canonical layout is already in place. There is nothing to migrate.

2. **Placeholder-ID transaction protocol** (journals, crash recovery): Disproportionate for a single-user local tool. However, strict write ordering (files → registry → config), temp-file-then-rename for JSON writes, and non-blocking advisory file locks on `config.json` and `_registry.json` are adopted as lightweight safeguards (see "What changes" §4). Full transaction journals remain rejected.

3. **Deep cgroup v2 container detection** (overlay mount inspection, `/etc/hosts` bind-mount source analysis, namespace-scoped signals): Adds significant complexity for an advisory message. `/.dockerenv` and `/run/.containerenv` cover the common cases.

4. **Versioned boot-hook JSON schema** (schema_version, forward-compatibility rules, consumer contracts): One producer, one consumer, one codebase. Change both when the format changes.

5. **`ARIA_RUNTIME_MODE` manual classification override**: Duplicates auto-detection and creates operator confusion.

6. **Cross-language slug sharing via `uv run python -c`**: Adds ~500ms overhead and a dependency on `uv sync` having been run, for a 4-line string transformation. Bash and Python each implement the documented contract; test vectors verify consistency.

7. **Tri-state isolation policy** (`warn`/`require`/`skip` with env var + config + CLI flag precedence, enforcement at two code paths, boot hook integration): Disproportionate machinery for a single-user advisory message. No adversary to enforce against. If enforcement is needed later, add it in a targeted proposal with a concrete use case.

8. **Standalone `docs/HOSTING.md`**: Platform support fits in the README compatibility block. A standalone doc is warranted only when Docker ships and needs container topology documentation.

9. **Placeholder registry entries from `aria-init` in fresh-clone case**: Creates entries that `.claude/scripts/aria-oauth-setup.py` must later reconcile. Simpler to let `aria-init` create files in a `0_{slug}` directory without a registry entry, and let OAuth setup handle full registration.

10. **Slug-matching placeholder directories to OAuth character names**: Matching `0_{slug}` directories by regenerating the slug from the OAuth-returned name is fragile — the user-typed name in `aria-init` may differ from the ESI-returned name (typos, abbreviation). The single-placeholder invariant is enforced by `aria-init` (fails fast if a different `0_*` exists) and by `.claude/scripts/aria-oauth-setup.py` (fails fast if multiple `0_*` found). Match by the `0_` prefix alone.

Phase 3 is lowest risk (removing dead code paths) and can land last.

## Risks, Mitigations, and Rollback

**Risk:** `aria-init` rewrite breaks first-run bootstrap.
**Mitigation:** Test on clean clone and on existing installation with populated `userdata/`.
**Rollback:** `git revert` the `aria-init` commits.

**Risk:** Bash and Python slug implementations diverge.
**Mitigation:** Contract explicitly specifies ASCII-only normalization with `[a-z0-9_]` character class. Bash uses `LC_ALL=C` and explicit ranges (not `[[:alnum:]]`). Python uses `re.sub(r'[^a-z0-9_]', '', s)` (not `str.isalnum()`). Shared test vectors — including Unicode and punctuation edge cases — validated in CI against both implementations.
**Rollback:** Fix the divergent implementation; existing registry entries are authoritative and never renamed.

**Risk:** `0_{slug}` placeholder directory is not renamed after OAuth.
**Mitigation:** `.claude/scripts/aria-oauth-setup.py` is modified to search for `0_*/` directories in `userdata/pilots/` after OAuth completes. Fails fast if multiple `0_*` directories exist (operator must resolve). Checks for rename collision before `mv`. Slug preserved from placeholder directory name (not regenerated from ESI character name).
**Rollback:** User can manually rename and update `_registry.json` and `config.json`.

**Risk:** Multiple `0_*` placeholder directories accumulate from repeated pre-OAuth `aria-init` runs.
**Mitigation:** `aria-init` checks for existing `0_*` directories before creating a new one. If a `0_*` directory exists with a different slug, `aria-init` exits with an actionable error message listing the existing directory and resolution options.
**Rollback:** User deletes the stale `0_*` directory manually.

**Risk:** Duplicate `{id}_*` directories exist from pre-invariant runs.
**Mitigation:** Single-user system with one pilot — current state has exactly one directory and one registry entry. The invariant is purely forward-looking defense. If duplicates are ever found, the error message lists both directories and asks the user to remove one.
**Rollback:** N/A — the invariant only adds a scan-before-create check.

**Risk:** JSON merge drops keys due to implementation error (e.g., `jq` filter rewrite instead of merge).
**Mitigation:** Test cases explicitly verify that non-core keys (`redisq` in config, `schema_version` in registry) survive updates. Both bash and Python implementations use read-modify-write, not construct-from-scratch.
**Rollback:** Restore `config.json` from git or from the corrupt-file backup.

**Risk:** `.claude/scripts/aria-refresh` continues to use system Python after migration.
**Mitigation:** Step 26a rewrites the wrapper to use `uv run python`. Test matrix includes explicit verification row. The wrapper is 22 lines; the change is a 3-line replacement of the interpreter resolution block.
**Rollback:** Restore the previous `python3`/`python` resolution block via `git revert`.

**Risk:** Operational scripts diverge from the pilot-selection contract after proposal ships.
**Mitigation:** Acceptance checklist covers all four scripts. The contract is documented in the implementation plan with explicit line references. Future scripts can reference this section.
**Rollback:** Scripts fall back to the pre-proposal behavior (silent first-pick), which is safe for single-pilot installations.

**Risk:** Runtime detection misclassifies environment.
**Mitigation:** Detection is advisory-only, non-blocking for supported platforms. Misclassification has no functional impact.
**Rollback:** N/A — no enforcement to disable.

**Risk:** Docker guidance is promoted before validation.
**Mitigation:** Docker is explicitly deferred to a future proposal. No Docker files or Docker-first language ships with this proposal.

## Proposed Decision

Approve as a phased implementation with three verification gates:

- **Phase 1 (Core Init + OAuth):** Make `aria-init` write to the paths the rest of the system reads from, with the filenames the rest of the system expects, using the interpreter the project requires, after verifying the interpreter is available. Include runtime detection, platform advisory, placeholder adoption, and the `aria-refresh` wrapper fix in the same phase.
- **Phase 2 (Runtime Auth Hardening):** Align all runtime credential resolution (`auth.py`, token refresh, boot sync, ESI sync, config validate) with the numeric-only + ambiguity-fail contract. Gate on Phase 1 verification. Phase 2 itself uses a deterministic hard gate (local/fixture tests) with live ESI as post-gate smoke only.
- **Phase 3 (Session-Support Cleanup):** Remove legacy path fallbacks from session-support scripts and update documentation. Gate on Phase 2 verification.

Each phase is independently revertable. Waterfall cutover — no migration machinery.

Defer Docker quick-start guidance to a separate future proposal contingent on MCP and OAuth validation gates. Native `uv` setup remains the recommended path until then.
